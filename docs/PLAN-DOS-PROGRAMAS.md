# Plan: split Distintive VM into two programs

**Status:** phases 1, 2 and 3 implemented (see [FASE-1.md](FASE-1.md), [FASE-2.md](FASE-2.md) and [FASE-3.md](FASE-3.md))
**Date:** 24/10/2026
**Project:** DesktopIdentifier (Delphi 12, Win32)

> **Final names:** the visible product name is **Desktop Identifier**; technical
> names keep the historical spelling: `DesktopIdentifier.exe` (configurator),
> `DesktopIdentifierHost.exe` (startup), `%LOCALAPPDATA%\DesktopIdentifier\` and
> the internal identifiers. Where this document says `DistintiveVM` or
> `DistintiveVMHost`, read those technical names.

---

## 1. Goal

Split the current program into two executables with clear responsibilities:

| Program | Executable | Role |
|---|---|---|
| Configurator | `DistintiveVM.exe` | Settings window, band generation, installation/uninstallation |
| Startup program | `DistintiveVMHost.exe` | Only the floating badge; as little code and footprint as possible |

Agreed premises:

- The startup program is installed **once** in a stable location on the machine.
- The configurator can live in the repository. If it is deleted, the badge keeps working.
- **Applying changes does not copy the host again or touch the registry**: it only writes the `.ini` (and the wallpaper).
- The top band is generated and applied by the configurator.
- What already works is kept: no administrator, per user, click-through, always on top, no taskbar or Alt+Tab.

---

## 2. Starting point

Today there is a single `DistintiveVM.exe` (VCL) that does everything:

| Unit | Current responsibility |
|---|---|
| `uBadge.pas` | Layered window (`TForm`), badge drawing, timer, DPI |
| `uConfigForm.pas` | Settings window (VCL, no DFM) |
| `uWallpaper.pas` | Composition, application and restoration of the band |
| `uGdiPlus.pas` | GDI+ drawing of the badge and the band |
| `uConfig.pas` / `uStartup.pas` / `uUtils.pas` | INI, startup with Windows, utilities |

Current size: ~2.6 MB (Release) and ~14.5 MB of RAM. All the VCL weight stays in a process that is always in memory, even though it only has to paint a window.

## 3. Decision 1 — Where to install the startup program

### 3.1 Requirements

- **R1.** It must still be there even if the configurator or the repository is deleted.
- **R2.** No administrator.
- **R3.** Consistent with per-user startup (`HKCU\...\Run`).
- **R4.** Easy to locate, update and uninstall.
- **R5.** The `.ini` must be accessible and writable by the configurator.

### 3.2 Options

| Option | R1 | R2 | Scope | Notes |
|---|---|---|---|---|
| `%LOCALAPPDATA%\DistintiveVM\` | Yes | Yes | Per user | Everything together: exe, ini and wallpapers. **Recommended** |
| `%LOCALAPPDATA%\Programs\DistintiveVM\` + data in `%LOCALAPPDATA%\DistintiveVM\` | Yes | Yes | Per user | Separates program and data; two paths to maintain |
| `%PROGRAMDATA%\DistintiveVM\` | Yes | No (admin) | All users | The ini would have to be separated per user or ACLs adjusted |
| `C:\Program Files\DistintiveVM\` | Yes | No (admin) | All users | "Formal" installation, but updating requires elevation |
| Next to the configurator / repo | No | Yes | — | Deleted with the repo: violates R1 |

### 3.3 Recommendation

**A single folder in `%LOCALAPPDATA%\DistintiveVM\`:**

```
%LOCALAPPDATA%\DistintiveVM\
    DistintiveVMHost.exe        <- startup program (runs at sign-in)
    distintive.ini              <- settings (written by the configurator)
    fondo-distintivo.png        <- wallpaper with band (generated by the configurator)
    fondo-original.dat          <- copy of the user's original wallpaper
    fondo-original.ini          <- path/style of the original wallpaper
```

Reasons:

- Meets R1–R5 without admin and without scattering files all over the machine.
- The uninstaller deletes a single folder and the user can inspect everything.
- The `.ini` stays next to the host: easy to edit by hand and to debug.
- Paths are centralized in one unit (`uPaths.pas`), so moving to `Program Files` or `ProgramData` later is a matter of changing one constant and separating data.

Assumed consequence: the installation is **per user**, just like the startup entry. In another Windows account it would have to be installed again (or switch to `%PROGRAMDATA%`, which would require admin).

> **Pending decision 1:** confirm this location or choose the variant with the exe in `%LOCALAPPDATA%\Programs`.

## 4. Decision 2 — How the startup program is configured

### 4.1 A single `.ini`

Yes: `distintive.ini` in the installation folder.

- The host reads it on startup and every time it receives the reload order.
- The configurator writes it with **atomic writes** (temporary file + `MoveFileEx`), so the host never reads a half-written file.
- It is editable by hand.
- **Only** the startup entry lives in the registry. There is no duplicated configuration.

### 4.2 Proposed schema

```ini
[general]
version=1

[cartel]
texto=A
color=#1473E6
color_texto=#FFFFFF
tamano=170
opacidad_panel=0.32
opacidad_letra=0.95
margen_derecha=30
margen_inferior=30
pantalla=0
esquinas=0.24
fuente=Segoe UI

[banda]
activa=1
color=#1473E6
alto=0.08
texto=
color_texto=#FFFFFF
alineacion=derecha
```

| Key | Type | Range / values | Notes |
|---|---|---|---|
| `cartel.texto` | text | any text | If empty, `A`. Replaces `letra` |
| `cartel.color` | color | `#RRGGBB` | Panel and border color |
| `cartel.color_texto` | color | `#RRGGBB` | Badge text color |
| `cartel.tamano` | integer | 90–280 | Pixels at 96 dpi; the host scales by DPI |
| `cartel.opacidad_panel` | real | 0.10–0.60 | Panel transparency |
| `cartel.opacidad_letra` | real | 0.30–1.00 | Text opacity |
| `cartel.margen_derecha` | integer | 0–1000 | Pixels |
| `cartel.margen_inferior` | integer | 0–1000 | Pixels |
| `cartel.pantalla` | integer | 0–8 | 0 = primary |
| `cartel.esquinas` | real | 0.00–0.50 | Corner radius, fraction of the size |
| `cartel.fuente` | text | — | Default `Segoe UI` |
| `banda.activa` | 0/1 | — | Whether the band is applied |
| `banda.color_sincronizado` | 0/1 | — | 1 = band color follows the badge color (default) |
| `banda.color` | color | `#RRGGBB` | Used when synchronization is off |
| `banda.alto` | real | 0.02–0.20 | Fraction of the screen height |
| `banda.texto` | text | any text | leave empty to hide the label |
| `banda.color_texto` | color | `#RRGGBB` | White by default |
| `banda.alineacion` | text | `derecha`, `centro`, `izquierda` | Text position |

### 4.3 Validation and compatibility

- The host **never fails** because of an invalid INI: every out-of-range value is clamped and, if the file does not exist, it uses the default values.
- The configurator validates the same in the UI (controls with minimums/maximums).
- On first installation, if the old `distintive.ini` exists (next to the current exe), its values are imported (`letra` → `cartel.texto`, etc.). The rest take the default values.
- `[general] version` is saved for future migrations.

### 4.4 Hot reload

- After saving, the configurator looks for the host window and sends it the registered message `DistintiveVM_RELOAD`.
- The host re-reads the INI, recalculates size/position and repaints without restarting.
- If the host is not running, the configurator starts it.

> **Pending decision 2:** does the `.ini` stay next to the host (recommended) or would you rather separate program and data?

## 5. Decision 3 — Division of responsibilities

| Task | Host (startup program) | Configurator |
|---|---|---|
| Read the INI | Yes | Yes (to edit) |
| Write the INI | No | Yes |
| Draw the badge | Yes | Only for the preview |
| Layered window, topmost, click-through | Yes | No |
| Generate and apply the band | No | Yes |
| Save/restore the original wallpaper | No | Yes |
| Copy the host into place | No | Yes (install/update) |
| Add/remove the entry in `HKCU\...\Run` | No | Yes (install/uninstall) |
| Close the host | Accepts `QUIT` | Sends `QUIT` |

### 5.1 Why the host without VCL

The host only needs its own Win32 window, a Win32 `TTimer` (`SetTimer`), GDI+ and to read an INI. With `Winapi.Windows` + `Winapi.GDIPAPI` + a hand-registered window, pulling in VCL (`TForm`, `TApplication`, `Controls`, `Graphics`…) is avoided, which is most of the current ~2.6 MB.

Measurable goal at the end of phase 1:

- Host size **< 1 MB** (Release, without debug information).
- Idle RAM **< 10 MB**.
- Immediate startup (no VCL initialization).

If it is not met, it is revisited (for example, using only the flat GDI+ API and its own INI parser without `System.IniFiles`/`Classes`).

### 5.2 Why the band is generated by the configurator

- Composing the image requires loading the original wallpaper, scaling it, drawing the band and saving a full-resolution PNG: it is the "fattest" part and it is only done when the user applies.
- Thus the host does not need `uWallpaper`, or codecs, or the original wallpaper: it only paints its badge.
- The band remains as a persistent desktop setting: it survives closing the host or the configurator.

Consequence: if the user changes the desktop wallpaper by hand, the band disappears. It is solved with a **Reapply band** button in the configurator (and it is documented). A "watchdog" that reapplies it will only be considered later (pending decision).

### 5.3 Why not a band window

A second window always on top would cover the top of maximized windows (title bar, menus). The band as part of the wallpaper does not intercept anything and looks exactly like part of the desktop, which is what is sought.

## 6. Proposed project structure

```
DistintiveVM.groupproj
src\
  common\
    uPaths.pas          fixed paths (LocalAppData, file names, Run value)
    uSettings.pas       settings model + INI parser/writer + validation
    uBadgeRender.pas    badge drawing with GDI+ (shared host/config)
    uUtils.pas          colors, DPI, helpers, registered messages
  host\
    DistintiveVMHost.dpr
    uHostWindow.pas     Win32 window, 32bpp DIB, UpdateLayeredWindow, timer
    DistintiveVMHost.manifest
    HostResources.rc    manifest + version
  config\
    DistintiveVM.dpr
    uConfigForm.pas     UI (VCL)
    uBandRender.pas     band drawing with GDI+
    uWallpaper.pas      wallpaper composition/application/restoration
    ConfigResources.rc  manifest + version + icon
```

- A **project group** with both `.dproj` files and a common output in `bin\`.
- The configurator looks for `DistintiveVMHost.exe` **next to itself** in order to install it. If it is missing, it shows a clear error ("host missing; build the whole group").
- Fixed names so that both find each other:
  - Host window class: `DistintiveVMHostWindow`.
  - Mutex: `Local\DistintiveVM_Host`.
  - Registered messages: `DistintiveVM_RELOAD`, `DistintiveVM_QUIT`.
  - Startup value: `DistintiveVM`.
- The host carries the `permonitorv2` manifest (no common controls, it does not need them).
- The configurator keeps its manifest with v6 controls.

## 7. Flows

### 7.1 Install (once)

1. Check that `DistintiveVMHost.exe` exists next to the configurator.
2. Create `%LOCALAPPDATA%\DistintiveVM`.
3. If the host is running, ask it to close.
4. Copy the host to the installation folder.
5. If `distintive.ini` does not exist, create it with the current UI values (or import the old one).
6. Write the `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\DistintiveVM` entry with the path of the installed host.
7. Start the host.
8. Show status: "Installed · Startup active".

Only this flow copies and touches the registry.

### 7.2 Apply (every settings change)

1. Validate and save the `.ini` (atomic).
2. If the band is active: save the original wallpaper (only the first time), compose the PNG and apply it.
   If not: restore the original wallpaper.
3. Send `RELOAD` to the host (or start it if it is not running).
4. The host is **not** copied. Nothing is written to the registry.

### 7.3 Update the host

When the configurator detects that the version of the installed host does not match its own:

1. Warn ("There is a new version of the startup program").
2. Close the host, copy the new one, start it.
3. The `.ini` and startup are not touched.

It is the only exception to "do not copy again", and it only happens when updating.

### 7.4 Session startup

1. Explorer processes `HKCU\...\Run` and launches `DistintiveVMHost.exe`.
2. The host reads the `.ini`, draws the badge and waits for messages.
3. The band is already applied (it is a desktop setting), it is not regenerated.

### 7.5 Uninstall

1. Ask for confirmation.
2. Send `QUIT` to the host; if it does not respond, terminate it.
3. Delete the `Run` entry (and the `StartupApproved` one if it exists).
4. Restore the original wallpaper if a copy was saved.
5. Delete the installation folder (with the option to keep the `.ini`).
6. Leave the desktop as it was.

### 7.6 Edge cases

| Case | Expected behavior |
|---|---|
| `Run` entry points to an exe that no longer exists | The configurator detects it and offers "Repair installation" or "Clean up" |
| Host installed but without `.ini` | Starts with default values; the configurator offers to save |
| Host running but not installed (started by hand) | The configurator warns and offers to install it |
| The user deletes the installation folder by hand | The badge disappears and the band may be left broken; the configurator detects the state and offers to reinstall/restore |
| The user changes the desktop wallpaper | The band disappears; **Reapply band** button |
| Multiple monitors | The band is replicated on each monitor (Windows applies the same image); the badge goes to the chosen monitor |
| Two host instances | The second one exits on its own (mutex) |
| The `.ini` is corrupt | The host uses default values and keeps working |

## 10. Tests

**Host**

- Visible window, without border, without taskbar, without Alt+Tab.
- `WindowFromPoint` over the center returns the window underneath (click-through).
- `GetWindowLong` with `WS_EX_LAYERED | TRANSPARENT | NOACTIVATE | TOOLWINDOW | TOPMOST`.

**Configurator**

- Install / apply / update / uninstall.
- Apply without copying or writing to `Run`.
- Band with different colors, heights and texts; exact restoration of the original wallpaper.
- Errors: host missing, no permissions, locked folder.
- Coherent preview.

**Regression**

- The desktop is left the same after uninstalling.
- No processes, keys or folders remain.
- Startup appears in "Startup apps" of Task Manager and can be disabled.

## 11. Risks

| Risk | Mitigation |
|---|---|
| Rewriting the host in pure Win32 introduces DPI/position bugs | Reuse the geometry logic and test at 96/120/144 dpi and several monitors |
| Two binaries that can get out of sync | Version in the exe + check when opening the configurator |
| The user deletes the configurator and cannot uninstall from the UI | Document manual deletion (folder + `Run` value); optional: host context menu later |
| Changing the wallpaper by hand removes the band | **Reapply band** button and note in the UI |
| Incorrect wallpaper restoration | Copy of the original + pixel restoration tests |
| Antivirus/SmartScreen with an unsigned exe | It is the same case as now; it does not change |
| The band is replicated on all monitors | It is documented; if it is a problem, consider a full virtual desktop image |

## 14. Summary of the proposal

The proposal was:

1. Tiny host (`DesktopIdentifierHost.exe`, Win32 without VCL) installed in `%LOCALAPPDATA%\DesktopIdentifier\`.
2. Settings in `desktopidentifier.ini` next to the host.
3. Install once (copy + `Run`); from then on, **Apply** only writes the INI and the wallpaper.
4. The band is generated by the configurator; the host only paints the badge.
5. Phase 1 = split without changing behavior; phase 2 = color/height/texts; phase 3 = polish.

All three phases are implemented; the result is in [FASE-1.md](FASE-1.md),
[FASE-2.md](FASE-2.md) and [FASE-3.md](FASE-3.md). Only the optional items
remain (tray, gradient/shadow and color copy).
